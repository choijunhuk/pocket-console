# 3DS, device compatibility and handheld UX implementation plan

**Goal:** Extend the verified DS app with real 3DS execution and improve the shared handheld experience. Carry Switch and Switch 2 as the subsequent execution targets, with honest engine readiness.

**User requirements:** Android; DS, 3DS, Switch and Switch 2; physical-console feeling; Galaxy S23 Ultra is the reference phone, while other capable Android devices must work; UI/UX matters.

**Architecture:** Azahar 2126.2 (`219d743a1e698101fe1ab8bef43e6563126c3c27`) in a dedicated `:three_ds` Android process. Build the libretro core from its checksum-pinned unified source for ARM64 and x86_64; use OpenGL ES 3.2 through an EGL offscreen frontend, preserving the existing DS adapter. Keep one fixed app-private Azahar user/save root across titles. The app has no game/firmware/key downloads.

## Decisions
- Use source builds for both ABIs so Android emulator acceptance is possible; the official prebuilt only covers Android ARM64.
- Build Azahar with upstream NDK 29.0.14206865 and static C++ runtime; the existing JNI/DS build remains on NDK 27.1.12297006. Cross-core calls use only the C libretro ABI; 3DS runs in its own process.
- `ENABLE_LIBRETRO=ON`, tests/Qt/SDL disabled, Vulkan OFF and OpenGL ON for this first frontend, built-in key blob OFF, LTO OFF, default 1x resolution.
- 3DS display is native 400x240 upper and 320x240 lower, with an actual circle-pad input and lower-screen touch.
- Classify device prerequisites from ABI/API/GLES/Vulkan capability, never a phone-name whitelist. Performance advice is distinct from a hard requirement; passing prerequisites is not game compatibility proof.
- Switch 2 uses a separate catalog target because `.nsp`/`.xci` names alone cannot distinguish it from Switch. Hokkaido is an experimental candidate, not a verified Pocket Console backend yet.
- Preserve the existing warm, tactile hardware world. Improve task flow and press feedback without changing the DS core or its save paths.

## Work lanes and ownership

## Integration interfaces
- `ThreeDsNative.open(String romPath, String userRoot, String systemRoot): long` throws IOException; load only packaged `libazahar_libretro.so` in the dedicated process.
- `ThreeDsNative.configuration(long token, int[] metrics): void` throws IOException; metrics are width, height, sampleRate, fpsMilli, with fixed 400x480 top/bottom composition expected for the initial layout.
- `ThreeDsNative.frame(long token, int[] pixels, short[] audio, int buttons, int touchX, int touchY, boolean touching, int circleX, int circleY): int` throws IOException; returns stereo frames, or -1 while no first video frame is ready. Pixels are ARGB 400x480, audio capacity 16384 shorts; touch is lower-screen 320x240; circle axes are -32767..32767.
- `ThreeDsNative.close(long token): void` throws IOException; GL/core cleanup on the emulation owner thread; stale tokens cannot close a newer session.
- `DeviceProbe.read(Context): DeviceCapabilities`; `DeviceCapabilities.check(ConsoleType): Compatibility`, where `Compatibility` has `State {READY, UNSUPPORTED, UNKNOWN}`, `reason`, and `advice`. This evaluates prerequisites only; engine readiness belongs in the UI.
- `ConsoleType.fromImport(String name, ConsoleType selected): ConsoleType` preserves legacy automatic classification except explicit Switch 2 selection for ambiguous `.nsp/.xci`; existing stored entries remain unchanged.
- `ThreeDsRomCache.copy(InputStream, File directory): File` creates an atomic digest-named private copy with a meaningful extension, validates 3DSX/ELF/NCSD/NCCH headers and bounds, and rejects unsupported encrypted content with clear errors. Root/model checks must not treat extension recognition as successful emulation.


### 1. Core build tooling
Files: `third_party/azahar.lock.json`, `scripts/prepare-3ds-source.py`, `scripts/build-3ds-core.sh`, `.github/workflows/3ds-core.yml`, `tests/test_azahar_source.py`.
- Pin Azahar 2126.2 unified source SHA256 `85c8b56fac703df04720125044b8ff887997911858a6cde545dfb1107ba4cd26`.
- Validate downloads/extraction and source version; cache reproducible build outputs keyed by lock, script and ABI.
- Build `azahar_libretro` for ARM64 and x86_64, publish renamed `libazahar_libretro.so` plus source/license manifest as artifacts.
- Prove both builds before shipping the combined APK; preserve complete license/source references.

### 2. Native graphics/frontend adapter
Files: `app/src/main/cpp/three_ds/*`; no DS adapter edits.
- Load only the packaged pinned core; implement libretro environment/options/input/audio/video and EGL GLES 3.2 context/FBO callbacks.
- Select `citra_graphics_api=OpenGL`, fixed top/bottom layout and 1x resolution; no Vulkan negotiation.
- Create context before calling core `context_reset`; use the actual framebuffer callback and flip readback as required.
- Keep ROM path and callback strings alive; validate file sizes/headers and report encrypted/unsupported/load/graphics failures.
- Own session IDs and GL/thread lifetime; serialize open/frame/close; keep the user path fixed and flush shutdown normally.

### 3. Capability model and file import
Files: `DeviceCapabilities.java`, `DeviceProbe.java`, `ConsoleType.java`, pure Java tests; coordinate shared callers.
- Add Switch 2 metadata and explicit selected-target handling for ambiguous Switch container extensions.
- Add 3DS homebrew formats used for executable acceptance, with content validation before native loading.
- Report actual API/ABI/GLES/Vulkan/RAM and core availability separately; no unsupported device-name claims.
- Test lower-end/unsupported/unknown capability cases, S23-class prerequisites, and ambiguous imports.

### 4. Handheld UI and player
Files: `DESIGN.md`, product/surface brief; then MainActivity/ConsolePreviewView, shared minimal UI styling, DS player visual refinements, new ThreeDs player/native facade/screen/circle pad/cache.
- Make import/play/resume and execution state clear; controller preview is a secondary action.
- Preserve 48dp targets and simultaneous input; add restrained press/ripple/haptic feedback respecting system settings.
- Portrait/landscape, cutouts, dark theme and font scale 1.3 must remain usable; tablet/split-window structure should not stretch phone controls.
- Errors preserve original files and saves. Distinguish ready, unsupported prerequisites, engine pending and experimental support.

### 5. Executable acceptance and integration
Files: original `tests/three_ds/*` homebrew, native smoke, Android instrumentation, CI integration, notices/docs.
- Build a small original 3DS homebrew without proprietary assets; require actual upper/lower frame output, input response and audio data where fixture produces it.
- Exercise the packaged x86_64 core and actual player on Android; retain DS smoke and save-manager regressions.
- Capture actual portrait/landscape/library screenshots and inspect them before further visual edits; keep visual verdict evidence scoped to supplied/generated references.
- Independent native/security/lifecycle and UI review; correct concrete failures, then integrate and push verified code.

## Switch 2 research boundary
As of 2026-11-11, Hokkaido 0.6.2 supplies an experimental Android fork with narrow maintainer-reported compatibility. Galaxy S23 Ultra and general Adreno/Mali support have not been reproduced here. Do not label a preview or filename classification as actual Switch 2 execution. The following Switch phase must validate source build, graphics/device requirements, original executable acceptance and phone limits separately.

## Verification limits
Local Gradle/ADB sockets and ordinary downloads are restricted; remote CI is available. No physical phone is connected. Build, emulator execution, screenshots, physical performance and game-specific compatibility remain distinct evidence.
