# DS Core Integration Implementation Plan

> **For agentic workers:** Execute the bounded native, Android-player and verification tasks in parallel where their interfaces are independent. The user authorized implementation and repository updates.

**Goal:** Run local DS documents inside Pocket Console using a pinned melonDS core; retain honest pending states for 3DS and Switch.

**Architecture:** Pin libretro/melonDS as a git submodule and reuse its Android.mk. A small platform-neutral C++ session adapter drives libretro callbacks, with JNI array transfer to an Android View/Bitmap and AudioTrack player. A private, SHA-256-addressed ROM copy gives stable save paths and avoids URI/name collisions.

**Tech Stack:** Existing Java 17/Android SDK 36, NDK 27.1.12297006, upstream libretro/melonDS `66b5d2634cd0a79030562811e6e05f5532f800ba`, platform audio/UI only.

**Spec:** `DESIGN.md`, `docs/architecture.md`, and user approval to proceed with DS first.

## Global constraints
- Keep repository private. Preserve imported catalog entries and source game documents.
- Only DS becomes launchable in this milestone; 3DS/Switch previews remain pending.
- No game/firmware/key downloads or proprietary BIOS bundled. Test an original generated homebrew image.
- Preserve upstream sources and license notices. Combined DS build follows the core's GPLv3+ terms; no public release in this task.
- CPU/core owns one session at a time. Session IDs prevent stale activity cleanup from closing a newer session.
- Game-internal `.sav` belongs under app-private saves and must survive stop/relaunch. No quick-save feature in this milestone.
- Prefer software 256x384, zero-gap Top/Bottom output first; no new UI/runtime dependencies.

## Review focus
- Malformed/truncated `.nds`: validate bounds before native load; no successful-execution claim from extension alone.
- Same filename/different bytes: separate digest paths; partial copies never replace the last valid cached ROM.
- Pause/rotation/finish: release buttons/touch, stop audio on pause, flush core save before unload, avoid cross-session races.
- Lower-screen touch: map only the actual lower display rectangle and clamp to 256x192.
- Output claims: headless ROM boot, Android APK build, emulator UI flow, and physical-device performance are separate evidence.

## Task 1: Native DS adapter
**Owner/files:** native executor; `app/src/main/cpp/{DsEngine.h,DsEngine.cpp,ds_jni.cpp,Android.mk,Application.mk}` only.
**API:** namespace `pocket`; `uint64_t open(const std::string& rom,const std::string& system,const std::string& saves)` throws `std::runtime_error`; `size_t frame(uint64_t token,int mask,int x,int y,bool down,uint32_t* pixels,size_t pixelCapacity,int16_t* audio,size_t audioCapacity)`; `void close(uint64_t token)`. Frame returns stereo frame count, pixels are ARGB 256x384; audio max 8192 shorts. Zero/stale token throws for frame; close is idempotent.
**JNI:** class `dev.pocketconsole.DsNative`: static native `long open(String,String,String) throws IOException`; static native `int frame(long,int[],short[],int,int,int,boolean) throws IOException`; static native `void close(long)`.
- [x] Add load/bounds/session checks and libretro callback adapter with stable game-info/ROM lifetime.
- [x] Configure DS/direct-boot/software/Top-Bottom/zero gap/touch, 32768Hz PCM, and private save/system directories.
- [x] Include upstream Android.mk module `retro`, add `pocket_ds`, shared C++ STL, flexible 16KB pages, arm64-v8a+x86_64.
- [x] Validate via host smoke and NDK CI rather than claiming local Gradle acceptance.

## Task 2: Android DS player and cache
**Owner/files:** Android executor; MainActivity.java, DsNative.java, DsPlayerActivity.java, DsScreenView.java, DsRomCache.java, tests/DsRomCacheTest.java, manifest and model-test script only.
**API:** consume JNI above. DsRomCache should be plain Java where possible; stable digest filename, bounded atomic copy, header validation; Android Activity opens URI off main thread. Libretro input mask: B0,Y1,Select2,Start3,Up4,Down5,Left6,Right7,A8,X9,L10,R11.
- [x] Write/run failing cache/header tests, then implement exact edge cases.
- [x] Launch DS entries inside app; provide clear load/error/pause state and keep other consoles pending.
- [x] Show real top/bottom output, lower-screen touch, simultaneous controls and stereo AudioTrack output.
- [x] Pause/resume/exit safely, preserve digest-based game saves; handle rotation without stale-session cleanup.
- [x] Keep style consistent with DESIGN.md and disclose any device/visual validation gaps.
